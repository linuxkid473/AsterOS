# Patch: dtrace bundled LLVM headers missing DataTypes.h

**Component:** dtrace-338.100.1 (`include/llvm-Support/`, used by `ctfconvert`'s `atom.cpp`/`strtab.cpp` via `llvm-ADT/DenseMap.h` -> `PointerLikeTypeTraits.h`)

**Problem:** `PointerLikeTypeTraits.h` does `#include "llvm/Support/DataTypes.h"`, but dtrace's bundled copy of the LLVM ADT/Support headers was flattened into `include/llvm-ADT/` and `include/llvm-Support/` (no `llvm/` prefix directory exists), and `DataTypes.h` itself — normally generated by upstream LLVM's build from `DataTypes.h.cmake` — was never included in this snapshot at all. Fails with `fatal error: 'llvm/Support/DataTypes.h' file not found`.

**Fix:**
1. Added `include/llvm-Support/DataTypes.h` containing what modern upstream LLVM actually generates for this file (`<cstdint>`, `<cstddef>`, `<inttypes.h>` — the legacy macro cruft this header used to contain is long gone upstream).
2. Changed the one `#include "llvm/Support/DataTypes.h"` in `PointerLikeTypeTraits.h` to `#include "DataTypes.h"` to match the flattened directory layout used everywhere else in this tree.

Matches the same fix independently found by Scott Knight when building this exact xnu/dtrace version (knight.sc blog, Feb 2020).
